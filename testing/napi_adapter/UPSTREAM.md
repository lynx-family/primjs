# UPSTREAM

This directory hosts the PrimJS N-API adapter unit tests. It is derived from the official Node.js test suites and adds a harness for multiple JavaScript engines.

- Upstream Project: Node.js (https://github.com/nodejs/node)
- Upstream Directories:
  - `test/js-native-api`: https://github.com/nodejs/node/tree/main/test/js-native-api
  - `test/node-api`: https://github.com/nodejs/node/tree/main/test/node-api
- Local `node` checkout commit: e1fc3dc2fcf19d9278ab59c353aa1fa59290378b
- License: MIT

## Motivation

The PrimJS N-API adapter aims to be compatible with the standard Node-API surface that existing native addons expect. To validate this, we reuse test cases from the official Node.js repository (`test/js-native-api` and `test/node-api`) and run them against PrimJS as well as other supported engines.

## Key changes vs upstream

- **Harness integration**
  - Introduce `napi_adapter_unittests.*` as a GoogleTest-based harness that can drive the js-native-api tests across multiple engines (V8, JSC, QuickJS, Harmony).
  - Provide a reusable runtime abstraction (`NAPIRuntime`) that plugs PrimJS N-API into the upstream tests.

- **Build system changes**
  - Replace the original Node.js build and test infrastructure with GN-based targets and a `build_js.py` helper that uses Browserify to bundle JavaScript tests.
  - Integrate with the `@lynx-dev/weak-node-api` package to supply the weak-linked Node-API implementation and headers.

- **Source adjustments**
  - Update C/C++ sources to include headers from `include/` generated by `@lynx-dev/weak-node-api` and to work with the weak symbol scheme.
  - Adapt JavaScript tests to load addons via a generic `./build/export` entry instead of Node.js-specific build outputs.
  - Where needed, add small polyfills or changes so that tests run correctly in the PrimJS environment.
