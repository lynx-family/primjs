# AGENTS.md

PrimJS is a QuickJS-based JavaScript engine for Lynx. `README.md` covers setup,
building, and running tests. This file lists only the constraints that are easy
to get wrong.

## Build And Test

- Use the build arguments and commands in `README.md`. As it describes, arm64
  Android, iOS, and macOS builds use tracing GC.
- Build tests with `python3 tools/ci/check_test_build.py` and run them with
  `python3 tools/ci/check_test_run.py`. The build script cleans and rebuilds
  every output directory, so after the first run rebuild only what you need
  with `ninja -C out/<dir> <target>`.
- Use `out/Default_snapshot`, which is a tracing GC build on arm64 macOS. The
  commands below write the directory as `out/<dir>`.
- Targets: `quickjs_unittest`, `napi_unittest`, `heap_unittest`,
  `qjs_debug_test`, `run_test262`, and `qjs_exe` (outputs `qjs`).
- Run gtest binaries directly and narrow them with `--gtest_filter`, for example
  `out/<dir>/quickjs_unittest --gtest_filter='CommonQjsTest.*'`.
- test262:
  `out/<dir>/run_test262 -m -a -c out/<dir>/quickjs_test/test262.conf`.
- JavaScript cases run through `qjs`:
  `python3 tools/ci/run_quickjs_unittests.py -b out/<dir>/`.

## Source And Build Files

- Adding or removing a source file requires updating both the owning `BUILD.gn`
  and `CMakeLists.txt`; the CMake list is used by the Android and HarmonyOS
  builds. A new source directory also needs an entry in `PrimJS.podspec`.
- `src/interpreter/primjs/interp/{android,ios,mac}/embedded*.S` are generated by
  `update_handlers.sh`; do not edit them by hand. In snapshot builds, GC
  runtimes run bytecode through these handlers instead of `JS_CallInternal` in
  `quickjs.cc`. The handlers are generated from
  `src/interpreter/primjs/codegen/` and bake in struct field offsets (see
  `codegen/accessBuilder.h`), so regenerate the files after changing bytecode
  semantics or those structs.
